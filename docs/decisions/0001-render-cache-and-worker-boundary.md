# ADR 0001: Versioned render cache и отдельный worker

- Статус: принято
- Дата: 2026-08-02

## Контекст

Telegram и Arena должны получать изображения без ощущения задержки. Рендер Pillow, загрузка карт и большие пользовательские фоны CPU/IO-intensive и блокируют event loop, если выполняются внутри обработчика. Обычный кеш только по deckstring некорректен: изменение дизайна или карточных ассетов должно создать новое изображение.

## Решение

Тяжёлый рендер выполняется прогретыми RQ workers. Ключ результата строится из канонического deckstring, нормализованных настроек дизайна, пользовательских asset fingerprints и явных версий renderer/template/card data. Одновременные одинаковые запросы дедуплицируются. Готовый JPEG хранится локально/CDN, а для Telegram дополнительно сохраняется `file_id`.

## Последствия

- Тёплый запрос обычно не запускает композицию и не загружает файл повторно в Telegram.
- Любое изменение дизайна или версии данных автоматически инвалидирует результат.
- Worker можно масштабировать независимо от bot/web процессов.
- Redis и очистка cache становятся операционными зависимостями.
- Производительность измеряется отдельно для cold render, warm render и Telegram delivery.
